# sec-audit

**Summary:** Conducts security audits, penetration tests, and control assessments to identify vulnerabilities, validate controls, and improve the organization's security posture.

**Level:** IC
**Reports to:** CISO
**Region variants:** NA, EMEA, APAC, LATAM

## Responsibilities
- Plan and execute security audits and penetration tests across networks, applications, cloud infrastructure, and systems.
- Assess security controls against industry standards (NIST, CIS, OWASP), regulatory requirements, and internal policies.
- Document findings, risk ratings, and remediation recommendations with clear technical detail.
- Validate remediation of identified vulnerabilities and control gaps through re-testing and verification.
- Develop and maintain audit methodologies, testing procedures, and penetration testing standards.
- Provide subject matter expertise on security best practices to engineering and operations teams.
- Define audit scope, objectives, and success criteria in collaboration with stakeholders.
- Perform web application security testing including vulnerability scanning and manual exploitation testing.
- Conduct network security assessments including external and internal penetration testing.
- Evaluate cloud security configurations across AWS, GCP, Azure, and hybrid environments.
- Produce executive-level summary reports that communicate risk in business context.
- Support security architecture reviews for new systems, applications, and infrastructure changes.

## Core Competencies
- Penetration testing and vulnerability assessment across web, mobile, API, network, and cloud attack surfaces.
- Security audit methodology and execution following recognized frameworks (NIST SP 800-115, OSSTMM, PTES).
- Technical security expertise spanning network security, application security, cloud security, and system hardening.
- Report writing and findings communication for both technical and executive audiences.
- Risk prioritization and remediation guidance for helping teams address findings effectively.
- Continuous learning and threat landscape awareness for staying current with attack techniques and vulnerabilities.
- Vulnerability research and exploit development for in-depth security assessments.
- Social engineering testing methodologies including phishing simulation and physical security assessments.
- Cloud security assessment expertise for major cloud providers and multi-cloud environments.
- Code review for security vulnerabilities in application source code.
- Security tool development and automation for efficient testing and reporting.
- Industry standard knowledge of OWASP Top 10, CWE Top 25, and MITRE ATT&CK framework.

## KPIs & Success Metrics
- Mean time to remediation (MTTR) for findings by severity — critical, high, medium, low.
- Vulnerability recurrence rate — percentage of previously reported findings reappearing in follow-up audits.
- Audit coverage — percentage of in-scope systems, applications, and infrastructure assessed.
- Remediation validation rate — percentage of remediated findings verified through re-testing.
- False positive rate — percentage of reported findings that are not reproducible or not exploitable.
- Audit cycle efficiency — time to complete planned audit scope versus budgeted hours.
- Stakeholder satisfaction with audit quality, clarity, and actionability.
- Zero-day and critical vulnerability discovery count from proactive testing.

## Career Progression
Security auditors and penetration testers typically start as junior pentesters or security analysts (0-2 years), progress to mid-level (2-5 years), senior (5-8 years), and lead/principal (8+ years). Growth involves expanding from executing individual tests to designing audit programs and leading testing teams. Senior testers lead complex engagements, develop new testing methodologies, and mentor junior team members. Career branching includes red team operations (more adversarial), security architecture, or product security. Many penetration testers come from software engineering, network engineering, or system administration backgrounds. Certifications are highly valued (OSCP, OSCE, GPEN, GXPN, CISSP, CEH). Bug bounty experience and CTF competition performance can supplement formal experience. Red team lead and security architect are common senior progression paths.

## Day-to-Day Workflow
A security auditor's week is driven by engagement cycles. Engagement phases include scoping (understanding target architecture, defining rules of engagement), reconnaissance (gathering information about targets), scanning (automated vulnerability discovery), exploitation (manual testing and validation), reporting (documenting findings and recommendations), and debrief (presenting results to stakeholders). Reconnaissance and scanning phases are automated and run in background. Exploitation requires deep focus — manual testing, chaining vulnerabilities, and creative attack paths. Reporting is the most time-consuming phase — documenting findings with technical detail, impact evidence, and remediation guidance. Debrief meetings present findings to technical teams and management. Between engagements, tool development, methodology improvements, and professional development fill the calendar. Continuous learning through CVE research, new tool evaluation, and practice in lab environments is essential. Collaboration with other team members includes peer review of findings and techniques.

## Cross-Functional Relationships
- **Security Engineering** — Partners on findings validation and remediation approach consultation.
- **Application Development Teams** — Primary stakeholders for application security audit findings and remediation.
- **Infrastructure / Cloud Teams** — Collaborates on network and cloud assessment scope and remediation.
- **DevOps / SRE** — Coordinates on infrastructure assessment scheduling, scope, and access requirements.
- **GRC Team** — Aligns audit methodology with compliance requirements and control testing framework.
- **Incident Response** — Shares findings that indicate active compromise or exploitation.
- **IT Operations** — Coordinates on system hardening assessments and configuration review findings.
- **Product Security** - Aligns on application security testing coverage and tool integration.
- **External Auditors** — Supports evidence collection and findings validation for external audits.
- **Legal / Compliance** - Consults on findings with regulatory implications or disclosure obligations.

## Regional Nuances
**NA:** Penetration testing and security auditing are mature fields with many specialized firms. High compensation for experienced testers, especially those with OSCP and advanced certifications. Bug bounty programs are widely adopted. Strong emphasis on automation and continuous security testing (DAST, SAST integration).
**EMEA:** GDPR data protection impact assessments may require security testing input. Growing certification body auditor market for ISO 27001. EU AI Act introduces auditing requirements for AI systems. Lower penetration testing rates than NA but strong quality of work. Data residency affects testing scope for cloud assessments.
**APAC:** India has a large penetration testing talent pool, both in-house and through consulting firms. China has its own security testing standards and certification framework (MLPS). Japan's security testing market emphasizes process and documentation. Singapore has growing security testing demand for financial services.
**LATAM:** Penetration testing services are often sourced through regional consulting firms. Growing in-house security testing teams in larger organizations. Lower rates for penetration testing services than NA. Talent development through certification programs is important for growing local capability. Offshore testing services for US companies from Brazil and Argentina.

## Industry Variations
**SaaS:** Audits focus on web application security, API security, and cloud infrastructure. Multi-tenant architecture testing for tenant isolation vulnerabilities. CI/CD pipeline security assessment. Customer data protection testing. Continuous testing integrated into development lifecycle.
**Fintech:** Regulatory-driven testing requirements — PCI DSS penetration testing, SOX ITGC testing, and FINRA requirements. Transaction and payment system security testing. Strong emphasis on cryptographic implementation review. Fraud-related testing for payment authorization flows. Strict rules of engagement given production financial systems.
**Healthcare:** Medical device security assessment requires specialized expertise (hardware, firmware, network interfaces). HIPAA security rule risk analysis requirements drive audit programs. Clinical system testing with patient safety considerations. IoT/OT security assessment for hospital environments.
**Manufacturing:** OT and ICS/SCADA security assessment requires specialized skills and safety-critical testing approaches. IT/OT boundary auditing. Plant floor system testing with production downtime constraints. Industrial protocol security analysis. Physical security assessment integration with logical testing.

## Common Challenges
- Getting development and operations teams to prioritize remediation of findings over feature work and operational tasks.
- Preventing test fatigue — teams becoming desensitized to findings when the same vulnerabilities are reported repeatedly.
- Maintaining thorough testing coverage within limited time and budget constraints.
- Keeping testing skills and tools current with rapidly evolving technology (cloud-native, Kubernetes, serverless).
- Gaining sufficient access and information for thorough testing without disrupting production systems.
- Communicating technical vulnerability information clearly to non-technical stakeholders who make remediation decisions.
- Navigating rules of engagement — balancing thorough testing against scope and damage limitations.
- Validating that remediation is effective without requiring full re-testing that creates dependency on the audit team.

## Key Regulations & Compliance
- PCI DSS Requirement 11 — penetration testing and vulnerability scanning requirements for cardholder data.
- NIST SP 800-115 — technical guide to information security testing and assessment methodology.
- HIPAA Security Rule — security risk analysis and testing requirements for healthcare.
- ISO 27001 — internal audit program requirements (Clause 9.2) for ISMS certification.
- SOC 2 Type II — penetration testing as part of security monitoring and control testing.
- FedRAMP — annual penetration testing requirements for cloud service providers.
- OWASP Testing Guide — web application security testing methodology standard.
- PTES (Penetration Testing Execution Standard) — penetration testing methodology framework.
- OSSTMM (Open Source Security Testing Methodology Manual) — security testing methodology standard.
- FINRA cybersecurity rules — penetration testing requirements for broker-dealers and financial firms.
- CMMC (Cybersecurity Maturity Model Certification) — testing requirements for defense contractors.
- GDPR — data protection impact assessments may require security testing of processing systems.

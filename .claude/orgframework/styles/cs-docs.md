# cs-docs

**Summary:** Technical Writer responsible for creating, maintaining, and optimizing customer-facing documentation, knowledge base content, and product guides that enable customer self-sufficiency and reduce support dependency.

**Level:** IC
**Reports to:** Support Director / Director of Content / Product
**Region variants:** NA, EMEA, APAC, LATAM

## Responsibilities
- Write, edit, and maintain customer-facing documentation including help center articles, user guides, getting-started tutorials, FAQs, and release notes
- Create and maintain API documentation, integration guides, SDK documentation, and developer portal content using OpenAPI/Swagger standards
- Develop onboarding materials, quickstart guides, and walkthrough content that reduce time-to-value for new users
- Own the knowledge base information architecture — structure, taxonomy, categorization, tag management, and cross-linking strategy
- Collaborate with product managers, engineers, and support teams to identify documentation gaps and content improvement opportunities
- Review and update existing documentation on a regular cadence to ensure accuracy, clarity, and alignment with the current product version
- Establish and maintain documentation style guides, writing standards, terminology glossaries, and voice-and-tone guidelines
- Optimize help center content for search engine discoverability (SEO) and in-product search relevance
- Manage content lifecycle — authoring, review cycles, versioning, localization, and deprecation
- Create multimedia content including product videos, annotated screenshots, GIF walkthroughs, and interactive tutorials
- Develop and implement documentation analytics to track content performance, search rates, and customer satisfaction with help content
- Write technical blog posts and thought leadership content that support developer relations and product marketing

## Core Competencies
- Technical writing excellence — ability to translate complex technical concepts into clear, accessible, user-friendly content
- Information architecture and content organization — designing intuitive documentation structures and navigation
- Content management systems, documentation platforms, and static site generators
- API documentation tools and standards (OpenAPI, Swagger, ReadMe, Stoplight, GraphQL documentation)
- Ability to understand product architecture and technical details across multiple domains
- Content strategy and editorial planning across documentation types and customer journey stages
- SEO and content discoverability optimization for documentation and help center content
- Style guide development and editorial governance
- Cross-functional collaboration with product, engineering, design, and support teams
- Multimedia content creation — screen recording, basic video editing, image annotation
- Analytics-driven content improvement — using data to identify content gaps and optimize existing content
- Localization and internationalization awareness for multi-language documentation
- Version control and documentation-as-code workflows (Git-based docs, docs pipelines)

## KPIs & Success Metrics
- Help center article satisfaction ratings and feedback scores
- Self-service success rate — percentage of support interactions that start and end in the knowledge base without ticket creation
- Content search relevance score — percentage of searches yielding a click on a result
- Documentation coverage — percentage of product features with complete and current documentation
- Time-to-find — average time for users to locate relevant documentation content
- Content freshness — percentage of articles updated within the last quarter
- Ticket deflection rate attributed to specific documentation improvements
- Localization completion percentage for target languages

## Career Progression
- **Junior Technical Writer (0-2 years):** Writes and updates help center articles under supervision. Manages content updates and revisions. Learns product domain and documentation tools. Develops writing skills with editorial feedback.
- **Technical Writer (2-5 years):** Independently owns documentation for a product area. Creates comprehensive guides and API documentation. Participates in content strategy. Proficient in documentation tools and publishing workflows.
- **Senior Technical Writer (5-8 years):** Leads documentation for complex product domains. Develops style guides and standards. Mentors junior writers. Drives content strategy decisions. Proficient in docs-as-code workflows and API documentation.
- **Lead / Principal Technical Writer (8-12 years):** Owns documentation strategy across the product portfolio. Manages information architecture and content operations. Drives documentation tooling and process improvements. Establishes documentation culture and best practices.
- **Director of Documentation / Head of Content (12+ years):** Leads a documentation organization. Sets content strategy aligned with business goals. Manages a team of writers and content specialists. Partners with product leadership on content investment.
- **Alternative paths:** May move into Product Management (deep product knowledge), Developer Relations (technical communication), Product Marketing (customer-facing content), or Content Strategy leadership.

## Day-to-Day Workflow
- Morning review of documentation queue — prioritize new articles, updates, and review requests based on product changes and support trends
- Content creation and editing — write new articles, update existing content, review submissions from subject matter experts
- Collaboration with product and engineering — attend product demos, review spec documents, interview engineers for technical accuracy
- Documentation review cycles — submit content for technical review, incorporate feedback, publish approved content
- Content analytics review — analyze help center metrics for top searches with zero results, low satisfaction articles, and content gaps
- Information architecture maintenance — review content structures, update taxonomies, fix broken links, improve cross-referencing
- API documentation updates — review API changes, update endpoint documentation, generate OpenAPI spec updates
- Support ticket analysis — review common support tickets to identify documentation gaps that could reduce ticket volume
- Localization coordination — prepare content for translation, review localized versions, manage glossary consistency
- Style guide maintenance — update writing standards based on product voice evolution and editorial best practices
- Weekly documentation team sync — align on priorities, review in-progress work, share user feedback and metrics
- Quarterly content audits — comprehensive review of documentation library for accuracy, relevance, and quality
- Communication rhythm includes deep writing focus time balanced with collaborative review and planning sessions

## Cross-Functional Relationships
- **Product (prd-manager, prd-owner):** Documentation requirements for new features. Product roadmap awareness for advance content preparation. Feature spec review for documentation needs. Release cadence alignment
- **Engineering (eng-backend, eng-frontend, eng-platform):] API documentation collaboration, technical accuracy reviews, code sample development, architectural understanding for documentation
- **Support (cs-tier1, cs-tier2, cs-tier3):** Primary knowledge base stakeholder — identifies documentation gaps from ticket trends. Reviews documentation for support team usability. Collaborates on internal vs. external documentation strategy
- **Self-Service (cs-self-service):] Help center content optimization for self-service, chatbot content integration, content categorization for AI-powered support flows
- **Customer Success (cs-success):] Documentation for onboarding and adoption programs. Content for customer health improvement campaigns. Customer-facing materials for QBRs and success plans
- **Design (dsg-ux, dsg-ui):** Visual asset creation, screenshot standards, diagram style consistency. UX writing alignment with documentation voice. Design system documentation coordination
- **Marketing (mkt-content, mkt-brand):** Content style and brand voice alignment. Blog content collaboration. Product launch content coordination. SEO content strategy alignment with marketing
- **Sales (sls-solutions, sls-enablement):** Sales enablement documentation needs. RFP response content. Competitive positioning documentation. Customer-facing technical content for evaluation processes
- **Legal (lgl-privacy, lgl-contracts):** Terms of service and privacy policy content coordination. Compliance documentation requirements. Disclaimer and liability considerations in technical documentation
- **Localization / Internationalization:** Multi-language content strategy. Translation vendor management. Glossary management across languages. Cultural adaptation of documentation

## Regional Nuances
- **NA:** Established technical writing profession with clear career paths. Docs-as-code approach is increasingly standard. API documentation and developer docs are high priority. Compensation $70K-$130K. Strong emphasis on SEO and content analytics-driven performance.
- **EMEA:** Multi-language documentation is a core requirement. English-first with translation to 5+ European languages common. Strong content strategy practices. EMEA-based technical writers often manage localization. GDPR-aware documentation practices. Compensation lower than NA with strong benefits.
- **APAC:** Growing technical writing profession. Multi-language documentation for APAC languages is critical (Japanese, Korean, Chinese, Thai, Vietnamese). Documentation quality needs to be high for Japanese and Korean markets where expectations are exacting. India has strong English-language technical writing talent.
- **LATAM:** Spanish and Portuguese documentation creation is essential. Often supports localization from English source content. Growing technical writing profession with increasing professionalization. Bilingual writers are highly valued. Lower compensation than NA.

## Industry Variations
- **SaaS:** Rapidly changing product requires continuous documentation updates. API documentation is critical for developer-centric products. Multi-version documentation for different release tracks. Self-serve documentation reduces support costs. In-app help and contextual documentation integration.
- **Fintech:** Compliance documentation alongside user documentation. Transaction lifecycle documentation. Regulatory disclosure content. Security and fraud protection documentation is critical. Precise, audit-ready documentation standards.
- **Healthcare:** Clinical workflow documentation. HIPAA compliance content. Regulatory submission documentation support. Safety-critical documentation standards. Provider-facing documentation differs from patient-facing. Versioning and change tracking for audit trail.
- **E-commerce:** Seller help center content differs from buyer content. Marketplace policy documentation. Shipping and returns documentation is high-volume. Seasonal content updates (holiday schedules, policies). Order management and tracking documentation.
- **Manufacturing/IoT:** Technical specifications and installation guides alongside user documentation. Safety documentation is critical. Firmware version documentation management. Field service documentation for repair technicians. Compliance and certification documentation requirements.

## Common Challenges
- Keeping documentation current with rapidly evolving product features and frequent releases
- Writing for diverse audiences — from non-technical end users to developer integration engineers — within the same documentation library
- Getting sufficient engineering and product time for technical review of documentation
- Measuring the business impact of documentation to justify content investment and resources
- Managing content scale — thousands of articles across multiple products, versions, and languages
- Balancing depth and readability — providing comprehensive coverage without overwhelming users
- Maintaining consistent terminology and voice across a growing library with multiple contributors

## Key Regulations & Compliance
- Accessibility compliance for documentation content — WCAG 2.1/2.2 AA standards for HTML documentation
- GDPR right to information — documentation must accurately describe data processing activities
- CCPA/CPRA privacy notice requirements reflected in documentation
- Terms of service and privacy policy accuracy in documentation
- HIPAA documentation requirements for healthcare products
- FDA documentation requirements for regulated medical devices and software
- SOX compliance for documentation related to financial systems and controls
- Trademark and copyright attribution standards in documentation
- Product liability implications — documentation must not contain misleading or inaccurate technical information
- Export control — technical documentation may be subject to EAR/ITAR controls for international distribution
- Industry-specific regulatory documentation requirements (FINRA, PCI-DSS, ISO standards)
- Open-source license attribution in documentation for third-party components

# dsg-ui

**Summary:** Creates visual design, component specifications, and design systems for web and mobile interfaces, ensuring visual consistency, brand alignment, and platform-appropriate execution.

**Level:** IC
**Reports to:** Design Director
**Region variants:** NA, EMEA, APAC, LATAM

## Responsibilities
- Design pixel-perfect visual interfaces for web and mobile applications across all breakpoints and device types.
- Build and maintain design systems, component libraries, and comprehensive style guides.
- Create detailed UI specifications, redlines, and asset handoffs for engineering implementation.
- Ensure visual consistency and brand alignment across all digital touchpoints and platforms.
- Collaborate with UX designers to translate wireframes and user flows into polished, high-fidelity interfaces.
- Stay current with UI trends, platform conventions (iOS Human Interface Guidelines, Material Design), and accessibility standards.
- Design iconography, illustrations, and visual elements that enhance the user interface.
- Create visual mockups, mood boards, and style tiles to communicate design direction.
- Define typography scales, color systems, spacing grids, and elevation/shadow systems.
- Conduct visual QA on implemented interfaces to ensure design fidelity in production.

## Core Competencies
- Visual design and typography with deep understanding of type selection, hierarchy, and readability.
- Design systems and component libraries for creating scalable, reusable UI patterns.
- Color theory and visual hierarchy for guiding user attention and creating visual order.
- Platform-specific design guidelines covering iOS, Android, Web, and emerging platforms.
- Accessibility and inclusive design including contrast ratios, touch targets, and screen reader compatibility.
- Prototyping and design tool mastery (Figma, Sketch, and emerging tools).
- Layout and responsive design for creating interfaces that work across all screen sizes.
- Attention to detail and pixel-level precision in every aspect of the visual interface.
- Design tokens and theming for supporting multi-brand and multi-theme systems.
- Frontend awareness to understand CSS capabilities, rendering constraints, and implementation feasibility.

## KPIs & Success Metrics
- Design system adoption rate across product teams (percentage of screens using system components).
- Component library coverage — percentage of product UI defined by design system components.
- Consistency score measured through audit of visual alignment, spacing, and color usage across products.
- Handoff quality — reduction in engineering questions and redesign requests per feature.
- Accessibility compliance rate (WCAG 2.1 AA pass rate across designed interfaces).
- Design-to-development cycle time reduction through design system efficiency.
- Visual QA pass rate on implemented features compared to design specifications.

## Career Progression
UI designers typically start as junior visual designers (0-2 years), advance to mid-level (2-4 years), senior (4-7 years), and staff (7+ years). Career growth focuses on depth of craft and breadth of system thinking. Senior UI designers lead complex, multi-surface design systems. Staff designers set visual direction for entire product portfolios. Some UI designers transition into UX or product design roles. Others specialize further into design systems, typography, or accessibility. Advancement requires a strong portfolio demonstrating system-level thinking, brand stewardship, and measurable impact on product quality. The rise of design systems as a discipline has created specialized career tracks for UI designers focused on system architecture and governance.

## Day-to-Day Workflow
A UI designer's day is centered on craft and system thinking. Mornings are typically reserved for deep design work — creating pixel-perfect components, refining visual details, or building out design system patterns. Mid-day involves more collaborative work: design critiques with the product team, handoff meetings with engineers, and reviews with UX designers to ensure visual alignment with interaction patterns. System maintenance is ongoing — adding new components, updating documentation, and reviewing component usage across teams. Regular audits check for visual drift and system compliance. Engineering pairing sessions help resolve implementation questions and refine handoff processes. Weekly design system guild meetings coordinate contributions from multiple designers. Monthly accessibility reviews ensure components meet evolving standards. Quarterly design system roadmap planning prioritizes new components and improvements.

## Cross-Functional Relationships
- **UX Designer** — Primary input source; translates wireframes and flows into polished visual interfaces.
- **Frontend Engineers** — Closest engineering partners; handoff and implementation support for visual components.
- **Design System Architect (if separate)** — Collaborates on system structure, token architecture, and governance.
- **Brand Designer** — Ensures UI components are consistent with brand identity and visual guidelines.
- **Motion Designer** — Coordinates on animation patterns, transitions, and micro-interactions within the system.
- **Product Designer (generalist)** — Collaborates on feature-level visual design within the system framework.
- **UX Researcher** — Incorporates usability findings into visual refinements and component improvements.
- **Accessibility Specialist** — Validates visual designs against accessibility standards and guidelines.
- **Engineering Platform Team** — Partners on design token implementation and developer tooling.
- **Mobile Engineers** — Adapts visual system for iOS and Android platform conventions.

## Regional Nuances
**NA:** Design systems are a mature practice with specialized roles and dedicated teams. Higher compensation for design system specialists. Strong emphasis on systems thinking and design operations. Remote collaboration across distributed teams is standard. Tools like Figma dominate the ecosystem.
**EMEA:** Strong European design traditions influence UI aesthetics — many influential design systems come from European companies (Nordic simplicity, Swiss design principles). Lower salaries than NA but strong work-life balance. Design systems are often built by smaller teams with greater autonomy.
**APAC:** Super-app ecosystems (WeChat, Grab, Gojek) drive unique UI patterns and component needs. Chinese UI conventions differ significantly from Western (denser information, more visual elements). India's mobile-first audience requires lightweight, bandwidth-sensitive UI. Japan's UI often uses more text and smaller type sizes reflecting character density.
**LATAM:** UI design is a growing field with increasing specialization. Many UI designers work as generalists covering both visual design and UX. Mobile-optimized UI is critical given high mobile-only user populations. Color and visual expression often reflect more vibrant cultural aesthetics compared to NA minimalism.

## Industry Variations
**SaaS:** Design systems focus on data-dense UI components (tables, charts, navigation). Multi-tenant UI patterns (workspace switcher, permissions UI) are system-level considerations. White-labeling and theme support are common requirements. Component documentation and self-serve design tooling for internal teams is important.
**Fintech:** Compliance and regulatory information display affects component design (disclosures, confirmations). Trust-inducing visual patterns (security badges, verification signals). Data visualization for financial information is a UI specialization. Dark mode support is often important given dark-pattern sensitivity.
**Healthcare:** Large touch targets and high-contrast UI for clinical environments. Print-to-digital UI consistency for patient portals. Medical terminology display and clinical data visualization are specialized UI challenges.
**E-commerce:** Product imagery and rich media UI components are system-critical. Multiple view modes (grid, list, gallery) and responsive product cards. Cart, checkout, and payment UI require specialized attention to reduce friction and errors. A/B testable components and personalization UI patterns.

## Common Challenges
- Maintaining design system adoption and compliance when product teams prioritize speed over system usage.
- Balancing design system standardization with product team autonomy and flexibility needs.
- Keeping pace with platform changes (iOS, Android, browser updates) while maintaining cross-platform consistency.
- Managing component complexity as the system grows — avoiding component bloat while covering use cases.
- Getting engineering buy-in for design system changes that require refactoring existing implementations.
- Measuring and communicating the ROI of design system investments to leadership.
- Onboarding new designers to the system and ensuring consistent usage patterns across a growing team.
- Resolving tension between brand team visual direction and platform-specific UI conventions.

## Key Regulations & Compliance
- WCAG 2.1 AA/AAA — all components must meet contrast, target size, and screen reader requirements.
- Section 508 — US federal accessibility requirements for government systems.
- ADA Title III — accessibility requirements for commercial digital products and services.
- iOS Human Interface Guidelines — Apple platform compliance for App Store approval.
- Material Design Guidelines — Google Android compliance for Play Store approval.
- GDPR — cookie consent UI and privacy preference center design patterns.
- EN 301 549 — EU accessibility standard for ICT products.
- Platform-specific accessibility APIs (iOS VoiceOver, Android TalkBack, Windows Narrator) compatibility.

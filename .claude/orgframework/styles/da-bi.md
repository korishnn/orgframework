# da-bi

**Summary:** Creates business intelligence reports, semantic layers, and self-service analytics tools that empower data-driven decision-making across the organization.

**Level:** IC
**Reports to:** Data Director
**Region variants:** NA, EMEA, APAC, LATAM

## Responsibilities
- Design and build business intelligence reports and dashboards that track KPIs and support decision-making.
- Develop semantic layers and data models for self-service analytics by business users.
- Manage BI tools and platforms including administration, user management, and license optimization.
- Optimize query performance and report loading times for a responsive user experience.
- Train and support business users on self-service analytics tools and best practices.
- Establish BI best practices, standards, naming conventions, and governance processes.
- Collaborate with business stakeholders to understand reporting requirements and translate them into BI solutions.
- Design data visualization approaches that effectively communicate insights and drive action.
- Manage BI content lifecycle including versioning, deprecation, and archival of reports and dashboards.
- Evaluate and implement new BI tools and technologies to improve analytics capabilities.
- Build and maintain data source connections and extract schedules for BI platform integration.
- Create executive dashboards and board-level reporting with appropriate data governance and access controls.

## Core Competencies
- BI tool expertise across major platforms (Tableau, Power BI, Looker, Qlik, Metabase).
- Data modeling and semantic layer design for creating business-friendly data abstractions.
- Report and dashboard design principles following visualization best practices and cognitive load management.
- SQL and data querying for data extraction, transformation, and optimization.
- User training and support for enabling self-service BI adoption across non-technical teams.
- Performance optimization for dashboards, queries, and report loads at scale.
- Data governance and access control for managing data visibility and permissions in BI platforms.
- Visualization design and storytelling for creating effective, impactful data communications.
- Stakeholder management for gathering requirements, managing expectations, and prioritizing work.
- Technical documentation for data models, report catalogs, and user guides.
- Extract, transform, and load (ETL) understanding for connecting BI platforms to data sources.
- Mobile and embedded analytics for delivering insights across devices and applications.

## Tools & Technology
- Business intelligence platforms (Tableau, Power BI, Looker, Qlik, MicroStrategy, Metabase, Apache Superset)
- Semantic layer tools (LookML (Looker), Power BI DAX, Tableau Data Models, AtScale)
- SQL query tools (DBeaver, DataGrip, Snowsight, BigQuery Console)
- Data integration and ETL tools (dbt, Fivetran, Stitch, Alteryx, Informatica)
- Embedded analytics SDKs (Looker Embed, Tableau Embedded, Power BI Embedded)
- Mobile BI platforms (Tableau Mobile, Power BI Mobile)
- Natural language query tools (Tableau Ask Data, Power BI Q&A, ThoughtSpot)

- Collaboration and knowledge management (Confluence, Notion for BI documentation)

## KPIs & Success Metrics
- BI platform adoption rate — active users, daily/weekly active usage across the organization.
- Self-service ratio — percentage of analytical questions answered by users without BI team intervention.
- Query performance P95 latency and improvement trends over time.
- Data freshness — latency between source data updates and BI availability.
- Stakeholder satisfaction score from periodic surveys of report consumers.
- Report/dashboard reuse rate — number of downstream consumers per published asset.
- Time from request to delivered report (cycle time for new reporting requests).

## Career Progression
BI professionals typically start as BI analysts or junior BI developers (0-2 years), progress to BI developers/analysts (2-5 years), senior BI developers (5-8 years), and BI architects/leads (8+ years). Growth involves expanding from report building to platform architecture and strategy. Senior BI developers design complex data models and lead dashboard projects. BI architects design the entire BI ecosystem including platform selection, semantic layer design, and governance frameworks. Career branching includes analytics engineering (more infrastructure-focused), business analytics (more domain-focused), or data management. Many BI professionals transition from data analysis roles. Certifications (Tableau Desktop Specialist, Power BI Data Analyst, Looker Certification) are valuable for career progression.

## Day-to-Day Workflow
A BI professional's day balances new development and operational support. Development work includes designing dashboards, building data models, writing calculated fields and measures, and optimizing performance. Support work includes troubleshooting reporting issues, answering user questions, and training new users. Requirement gathering meetings with business stakeholders define new report needs and prioritize the backlog. Weekly BI team stand-ups coordinate work and share best practices. User training sessions (group workshops or one-on-one) build self-service capabilities across the organization. Performance tuning of slow dashboards is ongoing — query optimization, data model refinement, and caching strategy improvements. Quarterly BI roadmap planning aligns with business priorities and platform evolution. Documentation of data models, report catalog, and user guides is maintained continuously.

## Cross-Functional Relationships
- **Data Analysts** — Collaborates on dashboard design and ensures reporting aligns with analytical best practices.
- **Data Engineers** — Partners on data model design, warehouse performance, and pipeline reliability.
- **Executives (CEO, CFO, COO)** — Primary consumers of executive dashboards and board-level reporting.
- **Finance Team** — Key stakeholder for financial reporting, budgeting dashboards, and variance analysis.
- **Marketing Team** — Requires campaign dashboards, channel performance tracking, and ROI reporting.
- **Sales Team** — Needs pipeline reporting, forecasting dashboards, and territory performance views.
- **Product Managers** — Use product analytics dashboards and feature adoption reporting.
- **Operations Team** — Requires operational dashboards for process monitoring and performance metrics.
- **HR Team** — Consumes workforce analytics, retention dashboards, and diversity reporting.
- **Data Governance Team** — Ensures BI assets comply with data governance policies and access controls.

## Regional Nuances
**NA:** BI is a mature field with well-defined roles. Cloud BI platforms dominate (Looker, Tableau Cloud, Power BI). Strong emphasis on self-service and data culture. High salaries and talent mobility. BI certifications are widely recognized and valued.
**EMEA:** GDPR compliance affects data access and visibility in BI tools. Multi-language reporting is often required. European BI tool providers (Qlik, Targit) have strong presence alongside global platforms. Works Councils may influence reporting on employee data.
**APAC:** BI tool adoption varies significantly by market — Looker and Power BI are strong globally, but local tools exist in China (FineBI, BDP). English proficiency impacts self-service BI adoption in some markets. Mobile-first BI reporting is more important given mobile usage patterns.
**LATAM:** BI is a growing practice with increasing tool investment. Power BI has strong adoption due to Microsoft's market presence. Training and support in local language (Spanish/Portuguese) is important. Budget constraints can limit access to premium BI platforms.

## Industry Variations
**SaaS:** BI focuses on subscription metrics, cohort analysis, funnel visualization, and customer behavioral reporting. Product analytics integration (Amplitude, Mixpanel) with BI platforms is common. Executive dashboards emphasize growth metrics, retention, and unit economics.
**Fintech:** Regulatory reporting dashboards with audit trail requirements. Risk and compliance reporting are critical BI use cases. Customer portfolio performance and financial analytics dashboards. Strict access controls for sensitive financial data in BI platforms.
**Healthcare:** HIPAA-compliant BI environments with patient data de-identification requirements. Clinical operations dashboards, population health reporting, and financial performance dashboards. Provider and payer analytics reporting with regulatory formatting requirements (HEDIS, Star Ratings).
**E-commerce:** Real-time sales and inventory dashboards for operational decisions. Marketing and campaign performance reporting with attribution. Customer analytics dashboards with segmentation and cohort views. Supply chain and fulfillment KPI tracking.

## Common Challenges
- Balancing self-service BI with data governance — enabling user exploration while maintaining data trust and consistency.
- Managing disparate data sources and data quality issues that affect BI report accuracy and trust.
- Keeping dashboard performance acceptable as data volumes grow and user bases expand.
- Getting business users to adopt self-service analytics when they prefer asking analysts for reports.
- Maintaining consistent metric definitions across different BI tools and user calculations.
- Managing the tension between standard templates and custom reporting needs from different departments.
- BI tool licensing costs that scale with user growth and may face budget constraints.
- Training diverse user populations with varying data literacy levels across the organization.

## Key Regulations & Compliance
- GDPR — data minimization in BI, right to explanation for automated decisions, user access controls.
- SOX — audit trail requirements for financial reporting dashboards and data integrity controls.
- HIPAA — PHI access restrictions in BI platforms and patient data de-identification requirements.
- CCPA — consumer data access and deletion request support through BI reporting.
- PCI DSS — cardholder data handling and masking in BI reports for payment analytics.
- SOC 2 Type II — BI platform security, availability, and confidentiality controls.
- Data governance policies — data classification labels and access restrictions in BI content.
- Internal controls — segregation of duties, approval workflows, and change management for BI content.
- Record retention policies — BI report archival and data retention schedules.
